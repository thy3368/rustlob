# AI coding之高价值软件门控系统

## 日抛软件与高价值软件的区别

## 为什么高价值软件需要门控

## 门控的核心原则

- 源码是唯一事实
- 需求和设计是意图与约束
- 优先计算型门控，后做概率型门控
- 优先左移，开发中反馈，提交前拦截，流水线兜底
- 公司统一规则 + 产品线扩展规则

## 门控的流程

- 开发期门控
- 提交前门控
- 合并前门控
- 发布前门控
- 线上缺陷反哺

## 门控对象分层

### 文档型门控

- 需求
- 架构设计
- 详细设计
- 需求/设计/代码漂移检查

### 源码型门控

- 语法规范 Lint
- 领域架构规范
    - 实体
    - 用例
    - 接口
    - 分层
    - 分模块
    - 分子系统
- 功能性
    - 单元测试（模块内部接口）
    - 集成测试（模块对外接口）
    - E2E测试（模块间）
- 非功能测试
    - 性能
    - 兼容性
    - 安全性
    - 可维护性

## 门控能力分型

### 计算型门控

计算型门控是指可以通过明确规则、程序执行、自动化测试、静态分析或度量指标完成的门控能力。它的特点是结果稳定、可重复、可解释，适合作为硬拦截。

典型能力包括：

- 编译
- Lint
- 类型检查
- 架构规则检查
- 单元测试
- 集成测试
- E2E 测试
- 覆盖率检查
- 性能基线检查
- 兼容性检查

### 概率型门控

概率型门控是指依赖 LLM 或其他概率模型进行判断的门控能力。它适合发现复杂语义问题、跨文档一致性问题、架构风险和潜在缺陷，但不宜在早期直接作为硬拦截依据。

典型能力包括：

- LLM Code Review
- 需求/设计/代码一致性分析
- 缺陷模式挖掘
- 架构风险识别
- 复杂业务逻辑审查

### 计算型门控与概率型门控的优缺点及适用场景

- 计算型门控：适合规则明确、低误报、可自动执行、可硬拦截的问题
- 概率型门控：适合语义理解、风险提示、未知问题发现、辅助人工评审的问题

## 落地优先级

### 第一阶段：公司级 Linter 硬门控

- 优先覆盖 AI 高频基础错误
- 优先建设低争议、确定规则、可自动化执行的检查项
- 公司统一建设通用规则
- 产品线补充业务与技术栈相关规则

### 第二阶段：领域架构规则门控

- 分层规则
- 模块依赖规则
- 实体、用例、接口边界规则

### 第三阶段：测试与质量基线门控

- 单元测试
- 集成测试
- E2E测试
- 覆盖率
- 性能基线

### 第四阶段：概率型辅助门控

- LLM Review
- 需求/设计/代码漂移分析
- 架构风险识别
