# Uncle Bob × Matt Pocock 对谈 可落地的方法论，

---

## 一、总原则：Human-as-Judge，不 Human-as-Reviewer
- **人不再逐行读 Agent 代码**，否则吞吐被锁死在人类阅读速度，Agent 的产能被你吃掉。
- **人定义“什么叫对”**：规格、验收、质量阈值、架构边界、风险点。
- **Agent 负责生成与自证**：写码、补测试、跑关卡、出证据报告。
- 信任来源 = 机器可复现的**红/绿/变异/指标**，不是“我觉得这行像对的”。

> 一句话：*Stop checking the cut. Build the gauge.*（别盯刀路，造量规）

---

## 二、约束体系：用“确定性工具”代替“长 Prompt 训话”
Prompt 里的规则会被 Transformer 的 **Lost-in-the-Middle** 软化（像《加勒比海盗》法典：“建议优先”），所以：

1. **System Prompt 极简**：只放最高优先级目标，挤进上下文“聪明区”。
2. **规则外置为可执行关卡**（Gauntlet）：
    - 单元测试 + 高覆盖率（分支/行）
    - **Gherkin / BDD 验收测试**（Given-When-Then，人话即规格）
    - 静态检查：lint、类型、圈复杂度（Cyclomatic Complexity）
    - **CRAP 分数**（复杂度×未覆盖率的复合指标，Agent 阈值可放宽到 6–8，人类 4 以下）
    - **变异测试 Mutation Testing**：自动改 `>` 为 `<`、`=` 为 `!=`，看测试能否抓到
    - 依赖方向校验（模块黑白名单）
    - QA 脚本化（UI 层端到端跑真实操作）
3. **人只看报告**：通过/失败、覆盖率、存活变异体数、CRAP 分布、依赖违规。

---

## 三、多 Agent 流水线：单 Agent 快但不稳，拆角色+短上下文
Bob 实际跑的接力（可裁剪）：

| 角色 | 输入 | 动作 | 输出 |
|---|---|---|---|
| Specifier | 人话需求 | 转 Gherkin + QA 步骤 | 可执行规格 |
| Coder | 规格 | 写单测+实现，跑通 Gherkin | 过红→绿的代码 |
| Cleaner | Coder 产物 | 降复杂度、拆函数、清重复 | CRAP 达标代码 |
| Hardener | Cleaner 产物 | 变异测试、补测试至 100% 覆盖 | 无存活变异体 |
| QA Agent | QA 文档 | 转脚本跑 UI 端到端 | 确定性通过报告 |
| Architect（人主导） | 架构查看器 | 定模块边界/依赖方向 | 规范文件（Agent 不可违） |

要点：
- **每个 Agent 出生→干活→死亡**，上下文不累积，规避“肥皂剧污染咖啡”的轨迹漂移。
- 并行编码 Agent 可多个同时跑，人笔记本也能撑 3+。
- 代价：启动 10–15s/个、角色间传递有通信税，但总体仍 2–4× 人类速度。

---

## 四、规划观：反“规格驱动开发（SDD）极致化”，回敏捷
- **不写厚重前期规格**：Agent 爱把计划写华丽但执行崩盘，瀑布式 SDD 在 AI 时代同样失效。
- **小步喂任务**：人给一两个具体故事 → Agent 做 → 人看架构/指标 → 手动调边界 → 再喂。
- **规格是转瞬即逝的**，最终代码即规格；人盯的是“结果长什么样”，不是“计划写多美”。
- 修改成本趋零时，反复试错比高价前期设计更划算（他那个“1 美元盖房”比喻）。

---

## 五、架构与模块：Agent 不擅长战略，边界必须人定
- Agent 容易把模块搞混、依赖反向；**Bob 至今仍亲自审模块划分**，再让 Agent 按依赖规范修。
- 工具化：
    - 架构查看器（类 UML，点模块下钻）
    - 依赖规范文件（A 可依赖 B，B 绝不可依赖 A，违者必须提取接口/反转）
- 偏好 **Deep Module（Ousterhout）**：窄接口宽实现，Agent 只读接口+测试即可动手，不被内部噪声淹。

---

## 六、人的新技能栈（底层基础反而更值钱）
- **战术编码让给 Agent**，人退到战略层：风险建模、验收设计、阈值标定、证据判读。
- 新人培养建议（Bob 原话变形）：
    1. 先自己写 1 年代码（含汇编/C 周末体验）→ 知道底层发生什么
    2. 进团队当“被人当 Agent 用的初级岗”→ 同套 Gauntlet 约束下干活几个月
    3. 能识别 Agent “挣扎”的信号（绕圈、自报处理不了、改 A 坏 B）→ 这只能靠老书+实战喂出来
    4. 再被授权“指挥 Agent 集群”
- **基础不过时**：复杂度、依赖、测试有效性、抽象边界——这些是喂给 Agent 的“量规原料”，不懂基础就调不准阈值。

---

## 七、最小可用闭环（团队今天就能抄）
不想上多 Agent，先跑这个：
1. 需求写成 Given-When-Then 验收点（含边界/异常）
2. Agent 写码必须带单测，红→绿
3. 一个 `make gauntlet` 命令串起：typecheck + lint + 单测 + 覆盖率门禁 + 变异测试 + 复杂度上限
4. 人只 Review：架构变动、权限/钱/并发、QA 报告、存活变异体列表
5. 超阈值（如变异存活>0、CRAP>8、依赖越界）自动打回 Agent 自修，到人眼前已是证据包

---

## 八、边界与警告（方法论不是银弹）
- 约束**过多会拖垮 Agent 速度**，平衡点未到极限但存在，目标维持 2–4× 人类即可，不为纯质量牺牲产能。
- 单 Agent 5 分钟出品不可信；完整流水线 1 小时换人类半天，是投资不是免费午餐。
- “不读代码”前提是你**有能力设计 Gauntlet**；没这能力，就是闭眼合并。
- Agent 目前**做不了**：长期战略、模块边界首创、业务风险权衡、对“错误类型”的取舍判断。
