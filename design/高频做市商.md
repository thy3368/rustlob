下面给你一版较体系化、可直接用于技术分享 / 架构评审 / 尽调材料的整理。  
定位是：做市商（从普通 MM 到 HFT）关注的 CEX 指标全景图，按“谁决定、看什么、为什么重要”三层结构组织。

做市商视角：CEX 指标评估体系

核心前提：做市商评估交易所，不是为了验证“谁更快”，而是验证

“我的策略在这套系统里能不能稳定赚钱、尾部风险是否可控、极端行情会不会被吃掉。”

因此，做市商关注的指标天然分成两类：

- 内生指标：CEX 架构 100% 决定，与用户网络/策略无关

- 合成指标：CEX + 网络 + 做市商自身共同决定，用于衡量“适配性”

一、微观执行质量（Execution Quality）

1. 时延与确定性（Latency & Tail Determinism）

指标 内生性 做市商关注点

撮合匹配时延（Matching Latency） ✅ 100% 内生 纯内存匹配耗时，微秒~亚毫秒；HFT 看 P99.9 是否稳定

行情分发单向时延（Market Data Distribution） ✅ 100% 内生 撮合完成 → 行情出网关；决定行情新鲜度

订单网关处理时延（Order Gateway Processing） ✅ 100% 内生 订单到网关 → 进撮合队列；不含网络去程

取消确定性（Cancel Guarantee） ✅ 100% 内生 Cancel-to-ACK 时延 + Cancel 是否保证在后续 Match 前生效

Tick-to-Trade（合成指标） ❌ 非内生 行情进 → 决策 → 发单 → ACK；含网络+策略，但 HFT 用来衡量端到端竞争力

尾部抖动（Jitter） ⚠️ 半内生 CEX 内部排队 + 网络共同决定；做市商要求极端行情下不退化

HFT 优先级：排队公平性 > 取消确定性 > 匹配尾部时延 > 行情分发确定性

2. 排队公平性与微观结构规则（Queue Priority Integrity）

这是 HFT 最在乎的指标，比时延更重要。

指标 内生性 说明

同价订单严格 FIFO ✅ 架构级决策

撤单重挂是否重置队列位置 ✅ 规则设计

部分成交后剩余订单是否保队列位 ✅ 撮合引擎实现

Modify（改量不改价）是否丢优先级 ✅ 有的所 modify = cancel+replace

批量下单队列分配规则 ✅ 同批到达订单的排序

自成交保护规则 ✅ 是否允许、如何处理

隐藏单（Iceberg）刷新逻辑 ✅ 展示量刷新规则

最小价格变动单位 / 最小订单量 ✅ 配置但影响策略

做市商原话："Tell me exactly where I stand in the queue, and never lie about it."

3. 订单类型与撮合语义

指标 内生性 说明

IOC / FOK / GTC / Post-only 语义 ✅ 撮合引擎实现

Post-only 在快速行情是否意外吃单 ✅ 行情与订单竞争顺序

部分成交行为 ✅ 剩余订单处理

跨交易对联动风控 ✅ 现货+合约联合保证金是否在同一状态域

二、流动性质量（Liquidity Quality）

1. 可执行深度（Effective Depth）

指标 内生性 说明

±1 / ±2 / ±5 / ±10 bps 深度 ❌ 非内生 取决于所有参与者，但 CEX 的撮合规则影响深度分布

大单冲击成本（VWAP 滑点） ❌ 非内生 同上

深度恢复速度 ⚠️ 半内生 行情恢复后做市商重新挂单的速度，受 CEX 限流影响

撤单率 / Cancel-to-Fill Ratio ❌ 非内生 但过高可能暴露 CEX 规则问题
2. 盘口质量
   指标 内生性 说明

Spread（买卖价差） ❌ 非内生 做市商自己报的

盘口稳定性（是否频繁闪单） ⚠️ 半内生 撤单规则 + 限流影响

行情合并策略 ✅ 100% 内生 是否合并成交事件、合并窗口大小

行情序列号连续性 ✅ 100% 内生 推送架构决定

三、API 与网关稳定性（API & Gateway Stability）

指标 内生性 说明

稳定速率 & 突发速率限制 ✅ 限流算法（令牌桶/滑动窗口）

撤单频率限制 ✅ 熔断保护设计

错误码确定性 ✅ 是否可重试、是否有歧义

Idempotency / Client Order ID ✅ 断连重发是否安全

批量撤单原子性 ✅ 逐条 vs 一次性

断连后订单状态可恢复性 ✅ 重连后能否查询到断开期间的成交

子账户 / 风控端点 ✅ 架构支持

维护/下币通知提前量 ✅ 运营流程

四、资金与成本效率（Funding & Cost Efficiency）

指标 内生性 说明

Maker / Taker Fee Tier ✅ 费率表

Market Maker Rebate ✅ 返佣规则

统一保证金 / 组合保证金 ✅ 架构级设计，跨品种对冲效率

资金费率（Funding Rate）频率与计算 ✅ 合约设计

借贷利率 / 保险基金规则 ✅ 风控架构

强平规则与 ADL 顺序 ✅ 清算引擎设计

五、极端行情韧性（Extreme Condition Resilience）

指标 内生性 说明

波动率飙升时 Spread 行为 ⚠️ 半内生 做市商撤单 + CEX 熔断规则

深度蒸发时撮合行为 ✅ 是否继续匹配、是否降级

API 限流/拒绝行为 ✅ 过载时是否 503、是否丢弃

熔断规则（价格带/只撤单模式） ✅ 触发阈值、恢复方式

插针保护 ✅ 是否有标记价格保护

充提暂停规则 ✅ 风控决策

热备切换时间 ✅ 故障恢复 RTO

切换期间订单处理 ✅ 丢失/重复/队列保留

六、一致性模型与状态可见性（Consistency & Visibility）

指标 内生性 说明

撮合引擎与资产账户一致性 ✅ 强一致 vs 最终一致

成交后头寸/余额可见时延 ✅ 资产服务内部处理

订单状态查询与推送一致性 ✅ REST vs WS 是否同源

成交推送投递语义 ✅ at-least-once / exactly-once

跨分片可见性延迟 ✅ 账户分片架构决定

七、指标优先级矩阵（按做市商类型）

做市商类型 第一优先级 第二优先级 第三优先级

HFT（高频） 排队公平性、取消确定性 匹配/行情尾部时延 限流透明度、微观结构规则

General MM（普通） 可执行深度、费用结构 API 稳定性、取消时延 资金费率、保证金效率

Options/Structured 结算价格确定性 标记价格规则 强平/ADL 规则

Arbitrage（跨所套利） 行情分发时延 跨所 latency arbitrage 窗口 充提速度

八、总结：做市商 vs 架构师 vs 普通用户的指标差异

角色 核心关注 最恨的事

普通用户 表面 TPS、提现速度、APP 体验 宕机、插针

架构师 一致性模型、单市场吞吐硬上限、恢复时间 口径切割、隐性耦合

做市商 排队公平性、取消确定性、尾部抖动、费用结构 排队规则不透明、Cancel 被 Match 吃掉、限流黑盒

九、一句话结论

做市商不关心 CEX 的“百万 TPS”宣传，他们关心的是：

- 我挂的单排第几（排队公平性）

- 我撤的时候单子还在不在（取消确定性）

- 行情炸了系统还稳不稳（尾部确定性）

- 规则透不透明、行为可不可预期（一致性+限流）

- 赚的价差能不能覆盖资金成本（费用+保证金效率）

> 这些指标里，前四项 100% 由 CEX 架构内生决定，是设计阶段就写死的，不是加机器能解决的。
